The private [Notion project headquarters](https://app.notion.com/p/3a71bdd385a4813d920cddc55f57669f) provides the readable stakeholder and portfolio view. Completed prototype work should be recorded retrospectively with evidence and an explicit retrospective label.

## Suggested Kanban columns

1. Backlog
2. Ready
3. In Progress
4. Review
5. Blocked
6. Done

Limit `In Progress` to a small number of items so brand decisions, operational work, and implementation do not fragment.

## Retrospective recording rule

When completed work is added after the fact:

- state that the issue is a retrospective record;
- describe the original problem and the delivered outcome;
- include acceptance criteria and verification evidence;
- link the relevant document, asset, or commit when available;
- use the actual completion date when known;
- never imply that a retrospective ticket existed before the work began.
